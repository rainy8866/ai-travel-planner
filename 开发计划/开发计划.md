## 0. 与 PRD v1.7 的关系

PRD 是"需求层"（做什么），本文件是"开发层"（怎么拆、规则怎么定、边界在哪）。

PRD v1.7 的核心主张（**全部必须遵守**）：
- **候选**：高德真实 POI + 按城市映射的安全库兜底 + confirm_keywords 白名单防噪声（防幻觉、防跨城污染、防挂羊头卖狗肉）；
- **排序**：直线距离 + 地理聚类 + 随机起点贪心（×2 取更短），不调距离矩阵 API；第 n+1 天种子锚定第 n 天**排好序后的最后一个 POI**；
- **提示词对齐（方案 A）**：Step1（出店名）+ Step3（编排）两段 Prompt 必须完整吃满用户 4 字段（城市/天数/节奏/兴趣标签），不再"半截上下文"；
- **大模型只编排不新增景点**；结果页顶部显式提示"本次 LLM/提示词是否生效"；
- **日志单次性 + 分组**：`reset_logs()` 清空历史，运行状态按 `(module, step, type, degraded)` 分组汇总；默认折叠的 expander；
- **输入页无默认值 + 轻量校验**：城市/标签都不用默认示例值，空了点击按钮给 warning 不进入下一步；不输出"游玩预算容量"提示；
- **开放时间硬约束**：编排引擎三层检查 open_time，POI 结束时间必须≤开放上限；
- **Cursor cap at soft_cap**：`_advance_cursor()` 防止边界 POI 导致 cursor 溢出；
- **全天 POI 跨时段**：duration≥480min POI 跨连续时段排列，cluster_days 独占一天；后续时段显示「⬅」；
- **Phase 1.5 跨天重分配（v1.7 规则统一版）**：收集所有天 dropped → 按天总空闲时长倒序 → 对候选天调用 `orchestrate_day(已排 + [p])` 重做完整试验 → p 排入（非 trial_out.dropped）则接受替换，保证与 Phase 1 同一套硬约束；
- **dropped 汇总显示**：所有未排入景点在最后一天后统一显示，不再分天；
- **地图默认底图 = 高德公开矢量瓦片**：从机制上保证"地图必定显示真实电子地图背景"，不再出现灰色画布；天地图要走瓦片探测真 200 才加进图层池；
- **结果页不提示编排规则来源**：不输出"本次行程由规则引擎编排..."文案。

本计划全部遵守这些，并补充开发决策与已拍板的改动。

## 1. 目录结构（方案 B：工作区写代码 → 同步到桌面）

```
项目根（工作区 = 桌面 旅行规划助手/）
├── app.py                  # Streamlit 入口（输入 → 候选 → 结果），只做薄串接
├── requirements.txt        # 依赖清单
├── .env                    # 本机密钥（不入库）
├── .env.example            # 密钥占位模板（入库）
├── README.md               # 项目简述/运行方式
├── ui/                     # UI 界面层：三个页面（方便单独改界面）
│   ├── input_page.py       #   输入页（仅 4 字段：城市/天数/节奏/兴趣标签；v1.3 无默认值+占位+轻量校验）
│   ├── selection_page.py   #   候选选择页（"美食探店"+"亲子乐园"下架、默认空勾选；v1.3 候选为空文案区分 Key）
│   └── result_page.py      #   结果页（不渲染午餐/晚餐，顶部 LLM/规则模式提示 + 运行状态分组）
├── 开发计划/               # 开发文档（本文件）
│   └── 开发计划.md
├── _config/                # 集中配置：常量、标签、时长基准、别名表、密钥模板、日志、高德瓦片端点
├── poi_pipeline/           # 模块一：候选生成与验证（防幻觉核心）
├── selection/              # 模块二：候选筛选 / 勾选 / 自动补缺（业务逻辑层，不含 UI）
├── routing/                # 模块三：直线距离 + 贪心排序（随机起点）
├── rules/                  # 模块四：时段分配 + 开放时间 + 规则引擎
├── render/                 # 模块五：大模型受控编排 + 后处理校验
├── map_view/               # 模块六：v1.3 默认=高德公开瓦片；瓦片探测才加天地图；folium.Map(tiles=None)
└── fallback/               # 模块七：异常兜底与降级链路（v1.3 日志不再甩锅高德 Key）
```

**约定**：
- `_config/` 可放 `.env.example`；各模块子文件夹只放 `.py`。
- **每个子文件夹（含 `ui/`）放一个空 `__init__.py`**，标记为 Python 包，保证 `app.py` 能 `import ui.result_page`、`from poi_pipeline import amap`，且可正常部署。
- **UI（`ui/`）与业务逻辑（各模块）分离**：UI 只负责布局/控件/展示，业务规则在各自模块。改界面只看 `ui/*.py`，不动业务代码。
- **模块文件夹一律字母开头**（`poi_pipeline / selection / routing / rules / render / map_view / fallback / _config / ui`）；已删除全部 `0X_` 前缀空文件夹（数字开头无法 `import`）。

### Key 预留与接入
- 高德 Key：`_config/config.py` 读 `AMAP_KEY = os.getenv(...)`；`has_valid_amap_key()` 非空即视为真配置；未填则选择页候选为空时提示注册。
- 天地图 Key：`_config/config.py` 读 `TIANDITU_KEY = os.getenv(...)`；**v1.3 不再直接 `has_valid_tianditu_key()` 就加图层，必须先走 `_probe_tianditu_tile()` 瓦片真 HTTP 200**。`.env.example` 预置 `TIANDITU_KEY=` 占位；**TIANDITU_KEY 不是必需**（默认走高德公开瓦片即可）。
- 接入流程：注册高德 Web 服务 Key → 填 `.env` 的 `AMAP_KEY=` → 重启自动生效，**代码无需改动**；天地图同理，但要注意选「服务端」类型 Key（浏览器端类型大概率瓦片 403 code=301012，会被探测机制挡掉）。
- DeepSeek `DEEPSEEK_KEY` 同理走 `.env`；未填时 render 走规则引擎降级，结果页变蓝提示。

## 3. 规则审查结论 → 定案改动

> 讨论确认过的改动，全部落地为"开发必做"，标注落点模块。

| # | 问题 | 定案 | 落点 |
|---|---|---|---|
| 1 | 推荐数(6/9) > 每日上限(5/7)，必触发排不下 | **日上限 = 时段数 × 每时段数**（正常 6、紧凑 9） | `rules` + `_config` |
| 2 | 开放时间走大模型=防幻觉后门 | **只展示、不硬过滤**，标注"仅供参考" | `rules` |
| 3 | 贪心起点未定义 | **随机起点 + 跑 2 次取总里程较短** | `routing` |
| 4 | 补缺均分在候选不足时会卡死 | **补不满就补多少 + 提示缺口未填满** | `selection` |
| 5 | 相似度≥60%未定义 | **关键词命中 + 编辑距离双判 ≥ 阈值** | `poi_pipeline` |
| 6 | 出游时长由 LLM 估算会打架 | **统一走 `_config` 内置基准库，LLM 只排版不改时长** | `rules` + `_config` |

### 3.1 各改动点补充

**改动点 1 · 日上限联动**
- `spots_per_period`: 轻松1 / 正常2 / 紧凑3；`max_poi_per_day` 强制 = 时段数 × 每时段数。
- 前提：用户选了哪些时段，日上限 = 选中时段数 × 每时段数。
  - 例：正常 × 早午晚3时段 = 6；只选早午2时段 = 4。
- `cluster_dist_km=5` 与日上限配套，改容量务必同步改聚类。

**改动点 3 · 随机起点**
- 每天内随机定 2 个起点，各跑一遍贪心，比较总**直线里程**，留较短者。
- 目的：路线有差异（不同人/不同跑不同）；又不偶发绕路。

**改动点 5 · 相似度双判**
- 大模型推的店名 + 高德返回名，用"关键词命中 + 编辑距离"双层判定是否视为同一地点。

**改动点 7 · 输入页无默认值（v1.3）**
- `city = st.text_input(..., placeholder="例如：杭州 / 成都 / 上海")`（**不要 value=**）。
- `tags = st.multiselect(..., placeholder="请选择兴趣标签")`（**不要 default=**）。
- 轻量校验：点击"生成候选景点"按钮时，先 `city = city.strip()`；`if not city: st.warning(...); return`；`if not tags: st.warning(...); return`。
- 天数、节奏允许有初值（Streamlit numberbox/selectbox 强制要求），因为它们不是"示例城市数据"。

**改动点 8 · 删除"亲子乐园"标签（v1.3）**
- `_config/config_data.py` 的 `INTEREST_TAGS` 字典中**整组删除**"亲子乐园" key。
- `ui/selection_page.py` 的 `_REMOVED_TAGS` 从 `{"美食探店"}` 扩展为 `{"美食探店","亲子乐园"}`。
- 安全库中 `SAFE_POI_LIBRARY["亲子乐园"]` 可留作闲置数据（不会被流程访问到，也不会报错）。

**改动点 9 · "候选为空"文案区分（v1.3 · 方案 A）**
- `ui/selection_page.py` 生成候选为空时的处理顺序：
  1. 先调 `has_valid_amap_key()`（读 `_config.config`，判断 `AMAP_KEY` 是否非空）。
  2. **Key 真缺失（False）** → 才显示「请注册高德 Web 服务 Key 并填入 .env 的 AMAP_KEY=」。
  3. **Key 正常（True）但候选池空** → 显示「当前城市这些标签暂时没有检索到足够候选。可能原因：内置安全库未覆盖『该城市 × 该标签』（目前主要覆盖杭州全标签、8 个主要城市的二次元标签），且高德未搜到足够匹配点位。建议更换城市或标签后重试。」
- `fallback/fallback.py` 的 `fake_candidates(city, tags)` 降级日志：把老的误导性文案「请配置高德 Key 或扩充 CITY_SAFE_POI_LIBRARY」改为「城市『{city}』标签 {tags} 无内置演示数据（安全库未覆盖该城市×该标签），高德亦未凑够候选，候选池为空」。

**改动点 10 · 地图底图方案 A（v1.3 · 真实电子地图保底）**
- 根因回顾：上一版两条底图链路同时掉链子 → ① TIANDITU_KEY 是"浏览器端"类型 → WMTS GetTile 返回 403 code=301012；② tile.openstreetmap.org 国内 connect timeout → PNG 拉不到 → 灰色画布。
- 解决方案（三步走，缺一不可）：
  1. **`_config/config.py` 新增高德瓦片端点常量**：
     - `AMAP_VEC_TILE = "https://webrd0{s}.autonavi.com/appmaptile?lang=zh_cn&size=1&scale=1&style=8&x={x}&y={y}&z={z}"`
     - `AMAP_SAT_TILE = "https://webst0{s}.is.autonavi.com/appmaptile?style=6&x={x}&y={y}&z={z}"`
     - `AMAP_SAT_ANNO_TILE = "https://webst0{s}.is.autonavi.com/appmaptile?style=8&x={x}&y={y}&z={z}"`
     - `SUBDOMAINS = ["1","2","3","4"]`
  2. **`map_view/map_view.py` 重写 `build_map()` 初始化**：
     - `m = folium.Map(location=..., tiles=None, ...)`（**`tiles=None` 是关键**，避免 folium 偷偷去拉 OSM 默认瓦片，等它超时/失败就会留灰底）。
     - 先调 `_add_default_amap_layers(m)` 铺四套真实电子瓦片：
       - 高德矢量底（show=True，默认选中）
       - 高德卫星底 + 高德卫星注记（叠层，show=False 可选）
       - OpenStreetMap（show=False 仅可选，不再当默认）
     - 再判断：`if has_valid_tianditu_key() and _probe_tianditu_tile():` → 才加天地图矢量 + 注记（show=False 可选）。
  3. **`_probe_tianditu_tile() -> bool` 必须真实发 WMTS GetTile 请求**（不能只看 Key 字符串非空）：
     - 用 requests 对 `https://t0.tianditu.gov.cn/vec_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0&LAYER=vec&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles&TILEMATRIX=10&TILEROW=340&TILECOL=858&tk={TIANDITU_KEY}` 发 GET；
     - headers 带 `User-Agent=浏览器 UA`、`Referer=http://localhost`；
     - 超时设 3s；**只有 HTTP 200 且 content 长度 > 0 才返回 True**；403 / 超时 / content-length=0 全部返回 False；
     - 返回 False 时打一条降级日志到运行状态：`log_error(module="map_view", step="瓦片探测", error_type="API", msg="天地图瓦片鉴权失败 http=403 code=301012 或超时，已跳过天地图图层", degraded=True)`。

**改动点 11 · Cursor 溢出修复（v1.5）**
- 问题：POI 恰好在时段 soft_cap 边界（如 12:00）放入时，cursor 变成 `12:00 + 15min 缓冲 = 12:15`，超过 soft_cap(12:00)，后续 POI 塞不进。
- 修复：新增 `_advance_cursor(slot, end_time)` 函数
  ```python
  def _advance_cursor(slot, end_time):
      _, _, _, sc = PERIOD_WINDOWS[slot]
      slot_cursor[slot] = min(end_time + SLOT_BUFFER_MIN, sc)
  ```
- 所有 cursor 更新统一走此函数，确保 cursor ≤ soft_cap。

**改动点 12 · 全天 POI 跨时段（v1.5）**
- 问题：duration≥480min POI（如青城山 8h）任何单个时段都塞不下，直接 dropped。
- 修复：
  1. `orchestrate_day`：尝试跨连续时段放置，标记已占用的时段 cursor = soft_cap
  2. `cluster_days`：种子 POI duration≥480min 时独占一天，不再贪心填充
  3. 移除 `full_day_exclusive` 阻塞标志：全天 POI 不阻塞其他时段普通 POI

**改动点 13 · Phase 1.5 跨天重分配（v1.5）**
- 问题：POI 在某天排不下直接丢弃，不尝试放到其他天空闲时段。
- 修复：`render_itinerary` 新增 Phase 1.5：
  1. 遍历所有天的 dropped 列表
  2. 对每个 dropped POI，尝试放到其他天的空闲时段
  3. 检查 open_time 约束
  4. 更新 cursor 和跨天去重集合 `global_used`

**改动点 14 · 开放时间硬约束（v1.5）**
- 问题：兜底逻辑忽略 open_time，导致武侯祠(08:30-18:30)被排到晚上。
- 修复：三层检查
  1. Phase 0 预解析：`parse_open_range(open_time)` → ot_rng 元组
  2. 主逻辑：`actual_end <= ot_rng[1]`
  3. 兜底：`if ot_rng is not None and actual_end > ot_rng[1]: continue`
- `parse_open_range` 迁移至 `_config/config.py`，解决 render/routing 循环导入。

**改动点 15 · 全天 POI 空闲标注（v1.5）**
- 问题：全天 POI 放在 morning 后，afternoon/evening 显示「（空闲）」误导用户。
- 修复：`_render_day` 检测 POI 的 time_range 结束时间是否超过当前时段 soft_cap，若超过则标记后续时段为「（全天景点占用）」。

**改动点 16 · 运行状态折叠（v1.5）**
- 问题：降级日志默认展开干扰用户视图。
- 修复：
  1. 运行状态改为 `st.expander("🛠 运行状态（调试信息）", expanded=False)`
  2. 移除 render.py 中"编排丢弃"的 `log_error` 调用

### 4.1 埋点规范（方案 A · 统一错误通道）

> 用来回答"哪个模块出错了"。每个模块出错时不直接 print，统一走一个集中记录器，带模块标识，便于日志检索定位。

**核心**：`_config/log.py` 提供三个函数：

```python
# _config/log.py (示意)
def log_error(module, step, error_type, msg, degraded=False):
    # 追加一行到 log/errors.log + 打到 stderr
    ...

def reset_logs():
    # 清空 log/errors.log（结果页生成前调用，保证单次性）
    ...

def read_logs():
    # 读取当前全部日志，供结果页按 (module, step, type, degraded) 分组
    ...
```

**字段约定**（所有调用方必须填齐）：
| 字段 | 含义 | 示例 |
|---|---|---|
| `module` | 所属模块，**必须与文件夹名完全一致** | `rules` |
| `step` | 该模块内的小步骤 | `时段分配` |
| `error_type` | 错误类型（约定枚举） | `LIMIT/API/OVERFLOW/TIMEOUT` |
| `msg` | 一句话描述 | `推荐6个超日上限5` |
| `degraded` | 是否为降级（False=真错误） | `True/False` |

**约束**：
- `module` 命名 = 文件夹名（`poi_pipeline`…`fallback` / `ui` / `map_view`），保证日志和目录一一对应。
- 降级也算一条日志（`degraded=True`），与真错误（`degraded=False`）同通道，统一可查。
- **单次性**：`app.py` 进入结果页前必须 `reset_logs()`，保证日志只反映本次请求。
- **v1.3 地图模块补充**：`_probe_tianditu_tile()` 失败时必须打一条 `degraded=True` 的降级日志（模块=map_view，step=瓦片探测，type=API），但只打 1 条，不要每张瓦片都打。

**怎么查**：本地用 `grep "module=rules" log/errors.log` 只看某个模块的错误行。
**落地**：写代码时每个模块引入 `log_error`，出错/降级处都上报。
